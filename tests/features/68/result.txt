Feature 68 - O86 Constant-Amount i16 Shift Specialization
========================================================

Status
------

The constant-shift specialization work is validated and the feature test case
now has a current post-refactor assembly snapshot in `v6clang_new02.asm`.
The remaining planned backend work is the dead-half omission subtask
(`MVI H,0` / `MVI L,0` removal when the discarded byte has no consumers), so
O86 is not marked complete in `design/future_plans/README.md` yet.


C Test Case Code
----------------

`c8080.c`

```c
typedef unsigned char u8;
typedef unsigned short u16;
typedef signed short s16;

u16 shl_u16_3(u16 x) { return (u16)(x << 3); }
u16 shl_u16_9(u16 x) { return (u16)(x << 9); }
u16 shl_u16_13(u16 x) { return (u16)(x << 13); }
u16 shl_u16_15(u16 x) { return (u16)(x << 15); }

u16 shr_u16_1(u16 x) { return (u16)(x >> 1); }
u16 shr_u16_2(u16 x) { return (u16)(x >> 2); }
u16 shr_u16_7(u16 x) { return (u16)(x >> 7); }
u16 shr_u16_9(u16 x) { return (u16)(x >> 9); }
u16 shr_u16_15(u16 x) { return (u16)(x >> 15); }

s16 sar_i16_7(s16 x) { return (s16)(x >> 7); }
s16 sar_i16_9(s16 x) { return (s16)(x >> 9); }
s16 sar_i16_15(s16 x) { return (s16)(x >> 15); }

volatile u16 g_u = 0x9234;
volatile s16 g_s = (s16)0x9234;
volatile u16 g_out_u;
volatile s16 g_out_s;

int main(int argc, char **argv) {
  (void)argc;
  (void)argv;

  g_out_u = shl_u16_3(g_u);
  g_out_u = shl_u16_9(g_u);
  g_out_u = shl_u16_13(g_u);
  g_out_u = shl_u16_15(g_u);

  g_out_u = shr_u16_1(g_u);
  g_out_u = shr_u16_2(g_u);
  g_out_u = shr_u16_7(g_u);
  g_out_u = shr_u16_9(g_u);
  g_out_u = shr_u16_15(g_u);

  g_out_s = sar_i16_7(g_s);
  g_out_s = sar_i16_9(g_s);
  g_out_s = sar_i16_15(g_s);
  return 0;
}
```

Observations
------------

- The biggest wins are the new short-right-shift and arithmetic-right-shift
  specializations: `shr_u16_7`, `shr_u16_15`, `sar_i16_7`, and `sar_i16_15`.
- `shl_u16_15` is now materially better than the old V6CLANG expansion because the
  old byte-lane + repeated `ADD A` sequence was replaced by `RRC + ANI`.
- `sar_i16_9` remains unchanged versus the old V6CLANG output on purpose. The
  shorter byte-lane-plus-one-step form is cheaper than the longer rotate/mask
  sequence for `>> 9`.
- `shl_u16_3`, `shl_u16_9`, and `shl_u16_13` were already in their good forms
  before the pseudo-family refactor, so the new backend preserves those wins.
