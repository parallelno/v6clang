Feature 72 — O90 Pre-ISel i8 Narrowing: Undo InstCombine PHI Guard Widening
===========================================================================

Status
------

O90 is implemented and validated.

InstCombine's `computeKnownBits` folds `icmp ne (trunc i16 (and i16 X, 1)), 0`
into `icmp ne i16 (and i16 X, 1), 0`, widening the comparison to i16.  When X
is a loop PHI with i16 siblings (like the lfsr16 pattern), the existing PHI
sibling guard in `V6ClangTypeNarrowing::tryNarrowAndConst` blocked narrowing,
forcing the full V6CLANG_AND16 pseudo (6 instructions, ~36cc per iteration).

The fix adds an `allUsersAreZeroTests` helper: when every user of the AND
result is an `icmp eq/ne %, 0`, the result never needs to be stored in a
register pair — only the flags matter.  The PHI sibling guard is bypassed,
the `and i16 X, C` (C ≤ 0xFF) is narrowed to `and i8 (trunc X), C`, and ISel
emits a single `ANI C` byte instruction (8cc, 2B) instead of 6 instructions.

The key mathematical identity: when C_hi = 0 (C ≤ 0xFF),
  `(and i16 X, C) == 0`  iff  `(and i8 (trunc X), C_lo) == 0`
regardless of X_hi, making the narrowing sound.


C Test Case Code
----------------

`v6clang.c` / `c8080.c`

```c
typedef unsigned char  u8;
typedef unsigned short u16;

/* 1. AND with small constant — pure zero-test (the lfsr16 pattern) */
u8 and_lsb_branch(u16 x) { return (u8)(x & 1) != 0; }

/* 2. AND with small constant — result returned as u8 */
u8 and_nibble(u16 x) { return (u8)(x & 0x0F); }

/* 3. OR with small constant — result returned as u8 */
u8 or_hi_bit(u16 x) { return (u8)(x | 0x80); }

/* 4. XOR with small constant — result returned as u8 */
u8 xor_pattern(u16 x) { return (u8)(x ^ 0x55); }

/* 5. AND with LARGE constant — control case, must NOT narrow */
u16 and_wide(u16 x) { return x & 0x0F0F; }

/* 6. AND in a loop with i16 PHI siblings — the lfsr16 pattern */
u16 lfsr_step(u16 lfsr) {
    u16 acc = 0, i;
    for (i = 0; i < 16; i++) {
        u8 lsb = (u8)(lfsr & 1);
        lfsr >>= 1;
        if (lsb) lfsr ^= 0xB4;
        acc ^= lfsr;
    }
    return acc;
}
```


v6clang OLD ASM (before O90)
-----------------------------

`v6clang_old.asm`:

```asm
and_lsb_branch:                     ; already narrowed (non-PHI, trunc path)
    MOV  A, L          ;  8cc, 1B
    ANI  1             ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

and_nibble:
    MOV  A, L          ;  8cc, 1B
    ANI  0xF           ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

or_hi_bit:
    MOV  A, L          ;  8cc, 1B
    ORI  0x80          ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

xor_pattern:
    MOV  A, L          ;  8cc, 1B
    XRI  0x55          ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

and_wide:                           ; control — C > 0xFF, not narrowed
    LXI  D, 0xF0F      ; 12cc, 3B
    MOV  A, L          ;  8cc, 1B
    ANA  E             ;  4cc, 1B
    MOV  L, A          ;  8cc, 1B
    MOV  A, H          ;  8cc, 1B
    ANA  D             ;  4cc, 1B
    MOV  H, A          ;  8cc, 1B
    RET                ; 12cc, 1B   — total 64cc, 10B

lfsr_step:                          ; INNER LOOP — PHI sibling guard blocks ANI
    ; setup: XCHG, LXI H,0, MVI A,0x10 (loop counter), STA (self-mod x2)
    ...
.loop:
    LXI  D, 1          ; 12cc, 3B   ← V6CLANG_AND16 constant load (16-bit!)
    MOV  A, C          ;  8cc, 1B
    ANA  E             ;  4cc, 1B   ← low byte of AND
    MOV  C, A          ;  8cc, 1B
    MOV  A, B          ;  8cc, 1B
    ANA  D             ;  4cc, 1B   ← high byte of AND (always 0, wasted!)
    MOV  B, A          ;  8cc, 1B   — V6CLANG_AND16: 7 insn, 53cc, 10B per iter
    ; ... RAR shift, ORA+JNZ zero-test, XOR feedback, XOR acc, DCR counter
```


v6clang NEW ASM (after O90)
----------------------------

`v6clang_new01.asm`:

```asm
and_lsb_branch:                     ; unchanged — was already optimal
    MOV  A, L          ;  8cc, 1B
    ANI  1             ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

and_nibble:                         ; unchanged — result trunc, not zero-test
    MOV  A, L          ;  8cc, 1B
    ANI  0xF           ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

or_hi_bit:                          ; unchanged (or not affected by O90)
    MOV  A, L          ;  8cc, 1B
    ORI  0x80          ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

xor_pattern:                        ; unchanged (xor not affected by O90)
    MOV  A, L          ;  8cc, 1B
    XRI  0x55          ;  8cc, 2B
    RET                ; 12cc, 1B   — total 28cc, 4B

and_wide:                           ; control — unchanged (C > 0xFF)
    LXI  D, 0xF0F      ; 12cc, 3B
    MOV  A, L          ;  8cc, 1B
    ANA  E             ;  4cc, 1B
    MOV  L, A          ;  8cc, 1B
    MOV  A, H          ;  8cc, 1B
    ANA  D             ;  4cc, 1B
    MOV  H, A          ;  8cc, 1B
    RET                ; 12cc, 1B   — total 64cc, 10B

lfsr_step:                          ; INNER LOOP — PHI guard relaxed by O90
    ; setup: XCHG, LXI H,0, MVI C,0x10 (loop counter narrowed to i8!)
    ...
.loop:
    MOV  A, E          ;  8cc, 1B   ← load low byte of lfsr
    ANI  1             ;  8cc, 2B   ← ANI 1 (i8 narrow, sets Z flag directly!)
    JNZ  .feedback     ;  8/12cc, 3B
    ; ... no 16-bit AND, no register pair spill, no ANA B
```

lfsr16 Benchmark Impact
-----------------------

O90 affects the lfsr16 benchmark (full LFSR over 65535 × 16 iterations).
The critical hot path is the `lsb = lfsr & 1` zero-test inside the inner loop.

Before O90: V6CLANG_AND16 emits `LXI rp,1; ANA E; ANA D` (6 instructions per iter).
After  O90: `ANI 1` (1 instruction per iter, sets Z flag, drives branch directly).

| Compiler      | Code size | Cycles     | vs v6clang |
|---------------|----------:|-----------:|------------|
| v6clang -O2   |     123 B | 1,410,320  | 1.00×      |
| c8080         |     176 B | 2,623,212  | 1.86×      |
| z88dk         |    1019 B | 4,473,860  | 3.17×      |

(Benchmark checksums all agree at 0x1D ✓)
